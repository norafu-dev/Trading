# Discord 图片归档到 Cloudflare R2

## 已确认方案

当前仅扩展 M1 采集：图片原始字节完整保存在私有 R2 Standard 桶，按频道 ID / 月份整理。
同频道、同月份内按 SHA256 内容去重；不同频道或月份独立保存，不做全局共享。
先保留全部原图，不启用生命周期删除、压缩或低频存储。容量累计后通过面板提醒，再根据
样本分析价值讨论保留期限。文字、附件元数据和消息历史版本仍保存在 PostgreSQL。

## 本地配置

1. 在 Cloudflare 创建一个 **Standard 私有桶**，位置使用默认自动选择，不选择 EU/US
   管辖限定；当前端点使用默认账户域名。不需要打开公开访问或配置自定义域名。
2. 创建仅限该桶的 **Object Read & Write** R2 API 凭证。这里需要的是 S3 的
   Access Key ID 和 Secret Access Key，不是 Discord Token 或普通 Cloudflare API Token。
3. 在项目本地 `.env` 添加下面字段。密钥不发到聊天、不填入前端、不提交版本库：

```dotenv
R2_ACCOUNT_ID=你的32位Cloudflare账户ID
R2_BUCKET=你的桶名
R2_ACCESS_KEY_ID=你的AccessKeyID
R2_SECRET_ACCESS_KEY=你的SecretAccessKey
MEDIA_WARNING_BYTES=8000000000
MEDIA_MAX_IMAGE_BYTES=25000000
```

4. 在项目目录执行 `make up`。它会加载环境变量、升级迁移、重新创建 API 和 Collector。
   只在 Docker Desktop 点击“Restart”不会读取已修改的 `.env`。
5. 打开采集面板的“图片归档”。“R2 已配置”仅表示字段已填写；成功图片和容量开始增加
   才说明上传链路已运行。再到消息页确认归档图片可显示，才完成上传及读取验收。

Collector 需要可用的 Discord Token 和消息访问权限。未配置 R2 时文字采集不受影响，
新图片任务随消息留存，旧快照会在 Collector 启动时分批补建任务。凭证配置完成后自动处理。

浏览器通过普通图片元素读取签名 GET；当前展示不使用 fetch/canvas，不要求 CORS。
以后如需在浏览器读取图片字节再配置相应 CORS。桶与账户应保持稳定；直接切换桶不能
迁移旧对象。应专用于本项目且不要手动删除已有对象。

## 链路与恢复

- 图片附件与 Embed 的大图、缩略图都进入归档队列，非图片附件保留原有链接。
- 消息、版本与图片任务同一事务提交。下载和上传运行于 Collector 内独立异步任务，
  同步 S3 SDK 放在线程执行，不阻塞 Discord Gateway 回调；优先归档较新的消息，避免历史
  补存挤压实时图片。当前单消费者，不新增 Redis。
- 下载仅允许 Discord CDN/代理 HTTPS 地址，禁止重定向，不携带 Discord Token。
  单图默认最多 25 MB，仅支持 PNG/JPEG/GIF/WebP/AVIF；原始字节不缩放、不转码。
- 链接返回 403/404 时通过已登录客户端重新读取原消息，匹配同一媒体稳定标识后下载。
  刷新只服务归档，不重写消息正文或生成新消息版本。编辑后换图、已删除或失去权限的
  历史图片可能无法恢复，会保留失败状态，不能拿当前新图代替旧图。
- 频道 ID、原消息月份和 SHA256 对应稳定对象键。同频道同月的多个消息可共用一个
  R2 对象，数据库已确认的对象不重复上传；跨频道、跨月份各自留存。
  上传成功但提交数据库前退出时，重试写回相同对象键，数据库只有一份对象记录。
- 任务领取后有 5 分钟租约，进程退出后由下一次运行回收。暂时错误按 1/2/4/8 分钟退避，
  最多 5 次正常处理失败；不能恢复的错误直接标记失败。面板可以主动重试失败图片。
- 数据库存对象键，页面使用稳定 `/api/media/{任务ID}`；每次访问都生成 1 小时签名并重定向，
  文件流量直接由 R2 提供。图片加载失败时显示原因和重新加载入口，不依赖永久 CDN 链接。

## 容量与备份边界

默认累计到 **8 GB** 时面板和运行事件提醒，不停止归档、不自动删除。统计只包含数据库
已确认的本项目独立对象字节，不含账户其他桶、操作请求、孤立对象或计费周期折算，不能
用来代替 Cloudflare 账单。原图保留不是备份：数据库与对象文件需要分别备份；数据库里的
对象键不能重建已删除的 R2 文件。

未来再根据每个 Trader 的样本价值决定按频道或消息类别的保留政策；本次没有后台自动
清理任务，也没有面板删除接口。仅显式目录迁移命令会清理已迁移的旧对象。
不存在的旧媒体、外部连接和云端账单都不能由本地测试验收。

实现依据：[R2 凭证与桶权限](https://developers.cloudflare.com/r2/api/tokens/)、
[Cloudflare boto3 接入](https://developers.cloudflare.com/r2/examples/aws/boto3/)、
[私有对象签名链接](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)。

## 目录规则与旧图迁移

新对象键为 `discord-images/{频道ID}/{YYYY-MM}/{SHA256}.{真实图片扩展名}`，例如：

```text
discord-images/
  123456789012345678/
    2026-09/
      图片哈希.png
```

使用稳定频道 ID，频道改名不影响历史路径。月份按原消息时间转换到 `Asia/Tokyo`
后计算，不按下载或补采时间；图片编辑后的版本仍归原消息月份。扩展名来自实际
图片格式检测，不信任远端文件名。不同频道或月份不共享物理文件。

数据库迁移 `0006_channel_media_layout` 将对象主键改为对象键，并保留现有旧路径引用。
之后执行 `docker compose exec -T collector trading reorganize-media`，先在 R2 桶内复制，
再流式读取并校验完整 SHA256 和字节数，通过后才事务切换消息引用，最后删除旧对象。
只允许清理本项目生成的 `discord-images/v1/{哈希前两位}/{完整哈希}`，遇到未知文件
停止。复制或校验失败不删除旧原图；中途退出可重跑，已切换引用的对象会再次校验后
继续清理。原消息正文和版本不变，稳定图片接口地址不变。

升级时需先停止旧版 Collector，再运行 `make up`，避免旧代码在数据库迁移后继续写入。
迁移命令可与新版 Collector 并行，新增图片直接进入新目录。用户已明确授权本次迁移
后删除旧目录文件；这不是日常留存策略，也不启用自动删除。

目录调整的 Docker 后端 Ruff、格式、迁移一致性和 66 项测试通过，覆盖跨频道/月份
独立存放、复制失败保护、删除失败后恢复和未知对象拒绝删除。前端接口契约不变，
本次未修改前端；前端检查结果来自此前归档功能验收。
